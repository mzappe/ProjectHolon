## Phase 0 — Foundation: Config Hardening & Space Recovery

> **Goal:** Lock down engine configuration, free saveblock/ROM space, establish a stable baseline before any branch merges.
> **Dependencies:** None — do this first.

### 0A. Commit pending config changes

- **Files:** `include/config/general.h`, `include/config/pokemon.h`, `GDDs/HL-106-design-bible.md`
- **Steps:** Commit the existing `configs-update` branch work, merge to `main`

### 0B. Disable all battle gimmicks

- **Method:** Config change only
- **File:** `include/config/battle.h`
- **Changes:**
  ```c
  #define B_FLAG_MEGA_RING        0
  #define B_FLAG_Z_RING           0
  #define B_FLAG_DYNAMAX_BAND     0
  #define B_FLAG_TERA_ORB         0
  ```
- **Also disable:** `B_AFFECTION_MECHANICS FALSE`, Sky Battles, Frostbite
- **Conflict risk:** None (config-only)
- **ROM impact:** Neutral (code compiled out by flags)
- **Verify:** Build, start new game, confirm no gimmick options appear in battle

### 0C. Free saveblock space (~3790 bytes)

- **File:** `include/config/save.h`
- **Set all `FREE_*` defines to `TRUE`:**

| Define | Bytes Freed |
|--------|------------|
| `FREE_MYSTERY_EVENT_BUFFERS` | 1104 |
| `FREE_MYSTERY_GIFT` | 876 |
| `FREE_RECORD_MIXING_HALL_RECORDS` | 1032 |
| `FREE_UNION_ROOM_CHAT` | 212 |
| `FREE_LINK_BATTLE_RECORDS` | 88 |
| `FREE_ENIGMA_BERRY` | 52 |
| `FREE_EXTRA_SEEN_FLAGS_*` | 160 |
| `FREE_BATTLE_TOWER_E_READER` | 188 |
| `FREE_POKEMON_JUMP` | 16 |
| `FREE_TRAINER_HILL` | 28 |
| `FREE_MATCH_CALL` | 104 |
| **Total** | **~3790** |

- **Conflict risk:** None
- **ROM impact:** Positive — frees ~3790 bytes of saveblock for Delta species data and quest state
- **Verify:** Build succeeds; save/load works in emulator with no corruption

### 0D. Species filtering & form disabling

- **File:** `include/config/species_enabled.h`
- **Changes:**
  ```c
  #define P_GEN_1_POKEMON         TRUE
  #define P_GEN_2_POKEMON         TRUE
  #define P_GEN_3_POKEMON         TRUE
  #define P_GEN_4_POKEMON         TRUE
  ```

- **ROM impact:** Large positive — removes thousands of species entries, sprites, data tables
- **Verify:** Build; Pokédex shows only Gens 1–4; no Mega/Regional form options anywhere

### 0E. Enable built-in QoL features

- **Files and changes:**
  - `include/config/item.h`: `I_REUSABLE_TMS = TRUE`, `I_EXP_SHARE_ITEM = GEN_6`
  - `include/config/overworld.h`: `OW_POPUP_GENERATION = GEN_5` (BW-style location popups)
  - `include/config/dexnav.h`: Enable DexNav and Search Levels (`TRUE`)
  - `include/config/caps.h`: `EXP_CAP_SOFT`; `LEVEL_CAP_FLAG_LIST` (to be tied to fragment milestones in Phase 2E)
- **Conflict risk:** None
- **Verify:** Build; test DexNav, TM reusability, and Exp Share in-game

### 0F. Enable HGSS Pokédex & Summary Screen

- **Files:**
  - `include/config/pokedex_plus_hgss.h`: Enable HGSS-style Pokédex
  - `include/config/summary_screen.h`: Gate IV/EV display behind `P_FLAG_SUMMARY_SCREEN_IV_EV_INFO` (unlockable via research tool in story)
- **Verify:** Pokédex UI is HGSS-style; IV/EV info hidden until flag is set

### 0G. ROM space recovery — Mega cries & Bard phonemes removal

- **Method:** Feature branches (targets expansion — low conflict risk)
- **Branches:**
  - `https://github.com/magical-ice-winged-otter/pokeemerald-expansion/tree/reduce-mega-cries`
  - `https://github.com/magical-ice-winged-otter/pokeemerald-expansion/tree/remove-bard-audio`
- **ROM impact:** Positive (significant audio data removed; Mega is disabled, Bard NPCs won't appear in Holon)
- **Steps:**
  1. `git checkout -b feature/audio-cleanup`
  2. `git remote add lordraindance https://github.com/magical-ice-winged-otter/pokeemerald-expansion`
  3. `git pull lordraindance reduce-mega-cries`
  4. Resolve any conflicts, build, test
  5. `git pull lordraindance remove-bard-audio`
  6. Resolve conflicts, build, test
  7. Merge to `main`

**Phase 0 verification:** Full clean build. New game boots, battles work, save/load works, Pokédex shows Gens 1–4 only, DexNav accessible, no gimmick options.

### 2C. Unbound Quest Menu — Major Manual Rework

- **Source:** `https://github.com/PokemonSanFran/pokeemerald/wiki/Unbound-Quest-Menu`
- **Conflict risk:** HIGH — targets base pokeemerald; no direct merge path into expansion
- **ROM impact:** Negative (new system, new graphics, new saveblock usage)

> [!WARNING]
> This is the most complex integration in the entire plan. The Unbound Quest Menu was built for base pokeemerald, not pokeemerald-expansion. Expansion has restructured the saveblock, flag/var ranges, script system, and start menu. **There is no clean merge path — this requires a full manual port.**

#### New files to create (port from Unbound source):

| File | Purpose |
|------|---------|
| `src/quest_menu.c` | Quest menu UI and logic |
| `src/quest_log.c` | Quest state tracking |
| `include/quest_menu.h` | UI header definitions |
| `include/quest_log.h` | Quest data structures |
| `include/constants/quest.h` | Quest ID constants |
| `data/quest_data.h` | Quest definitions (names, descriptions, objectives) |
| `graphics/quest_menu/` | UI graphics (icons, frames, completion markers) |

#### Existing files that need modification:

| File | What to add | Why it differs in expansion |
|------|-------------|----------------------------|
| `src/main.c` | Quest system initialization | Expansion has additional init calls |
| `src/start_menu.c` | Quest Log menu entry | Expansion restructured start menu |
| `src/event_data.c` | Quest flag/var management | Expansion uses different flag ranges |
| `src/script.c` | Quest script commands | Expansion has additional script commands |
| `asm/macros/event.inc` | Quest script macros | Expansion has additional macros |
| `include/global.h` | SaveBlock fields for quest state | Expansion SaveBlock structure differs significantly |
| `include/constants/flags.h` | Quest completion flags | Expansion uses different flag numbering |
| `include/constants/vars.h` | Quest tracking variables | Expansion uses different var numbering |
| `src/save.c` | Quest data in save structure | Expansion save structure is modified |

#### Step-by-step porting guide:

1. **Study the Unbound implementation** — Read the wiki page completely. Clone the source. Map every file the quest system touches.

2. **Map the SaveBlock differences** — Compare Unbound's `include/global.h` SaveBlock structs with expansion's. Identify where quest data fits in the space freed in Phase 0C.

3. **Define the quest data structure:**
   ```c
   struct QuestData {
       u8 questId;
       u8 state;            // QUEST_INACTIVE, QUEST_ACTIVE, QUEST_COMPLETE
       u8 currentObjective;
       u16 flags;           // bitfield for sub-objectives
   };
   ```
   Budget: ~20 bytes per quest × 50 quests = ~1000 bytes (within the 3790 freed in Phase 0C).

4. **Port `quest_menu.c` and `quest_log.c`** — These are mostly self-contained UI files. Adapt graphics/window rendering calls to expansion's updated system.

5. **Port script macros** — Add quest macros to `asm/macros/event.inc`:
   - `queststart <quest_id>`
   - `questcomplete <quest_id>`
   - `questobjective <quest_id> <objective>`
   - `checkquest <quest_id>` (returns result in `VAR_RESULT`)

6. **Integrate with start menu** — Expansion's `src/start_menu.c` differs from base pokeemerald. Add a "Quest Log" entry that calls the quest menu UI.

7. **Adapt flag/var ranges** — Find available `FLAG_UNUSED_*` ranges in `include/constants/flags.h` and allocate quest flags there.

8. **Port graphics** — Copy quest menu sprites; convert to expansion's expected indexed PNG format if needed.

9. **Test incrementally:**
   - Quest menu opens from start menu (empty list)
   - A test quest activates via script
   - Quest objectives track correctly as flags are set
   - Quest completion triggers configured rewards

## Phase 4 — Delta Species System

> **Goal:** Build the core mechanic that defines the entire game.
> **Dependencies:** Phase 0 (species filtering, saveblock freed), Phase 2C (quest system for Delta discovery tracking).
> **Note:** This is entirely custom work with no feature branch to merge. It is the single largest technical undertaking in the project.

### 4A. Architecture Decisions

**Species slot strategy:**
- Each Delta Pokémon = a new species entry (same approach as Alolan forms in expansion)
- Naming convention: `SPECIES_CHARIZARD_DELTA`, `SPECIES_MEWTWO_DELTA`, etc.
- Estimated count: ~100–150 Delta species based on `holon_pokedex_v2.csv` (TCG set mapping)
- With Gens 5–9 disabled, there is significant species ID headroom in the constants

**Key files per species (expansion's simplified ~5-file system):**

| File | Purpose |
|------|---------|
| `src/data/pokemon/species_info/{family}.h` | Stats, types, abilities, Pokédex text |
| `src/data/pokemon/level_up_learnsets/gen_6.h` | Level-up learnsets (Gen 6 era) |
| `src/data/pokemon/evolution.h` | Evolution methods |
| `src/data/pokemon/egg_moves.h` | Egg moves |
| `include/constants/species.h` | Species ID constants |

**Delta-specific data per species:**
- Modified typing (the core mutation — primary change from base species)
- Custom sprites: front (80×80), back (80×80), icon (32×32) per HL-300 Pixelorama workflow
- Adjusted learnsets blending base moves with new-type moves
- Custom Pokédex entry describing the Delta mutation
- Cry: reuse base species cry unless a unique cry is authored

### 4B. Implementation Steps

1. **Define the Delta roster:** Cross-reference `GDDs/holon_pokedex_v2.csv` with Gens 1–4 species. Finalize every Delta Pokémon with confirmed mutated types.

2. **Add species constants** in `include/constants/species.h`:
   ```c
   #define SPECIES_CHARIZARD_DELTA    (SPECIES_EGG + N)
   #define SPECIES_MEWTWO_DELTA       (SPECIES_EGG + N + 1)
   // ... etc., numbering from available ID range
   ```

3. **Create species_info entries** in `src/data/pokemon/species_info/`:
   ```c
   [SPECIES_CHARIZARD_DELTA] = {
       .baseHP        = 78,
       .baseAttack    = 84,
       // ... same base stats as Charizard
       .types         = MON_TYPES(TYPE_FIRE, TYPE_STEEL),  // Delta mutation
       .abilities     = { ABILITY_BLAZE, ABILITY_NONE, ABILITY_TOUGH_CLAWS },
       .speciesName   = _("Charizard"),
       .description   = COMPOUND_STRING(
           "A Charizard warped by the Tower's\n"
           "electromagnetic field. Its scales have\n"
           "hardened into a metallic alloy."),
       // ... etc.
   },
   ```

4. **Create custom sprites** following the HL-300 Pixelorama workflow:
   - Copy base species sprite files as starting point
   - Recolor using HSV palette shifts per the HL-300 type-to-hue reference table
   - Export as indexed PNG (not RGBA)
   - Place in `graphics/pokemon/{species_name}_delta/` matching expansion's file naming convention

5. **Create learnsets** in `src/data/pokemon/level_up_learnsets/gen_6.h`:
   - Blend base species moves with moves matching the new type
   - Remove moves that would be lore-inconsistent with the mutation

6. **Add to Pokédex:** Configure Holon Regional Dex to show Delta species alongside their base forms. Delta entries should display the mutation type prominently.

7. **Add to encounter tables** matching lore-defined saturation rates from HL-104:

   | Zone | Delta encounter rate | Metal-type prevalence |
   |------|--------------------|-----------------------|
   | Mirage Forest | ~50% | Moderate |
   | Holon (near Tower) | ~50% | High (~100%) |
   | Holon Lake | ~96% | Moderate (~39%) |
   | Unnamed Island | ~26% | Moderate (~40%) |
   | Dragon Frontiers | 100% | None (0%) |

8. **Add evolution methods:** Delta species evolve into other Delta species using expansion's stackable evolution conditions.

### 4C. Saveblock Allocation for Delta Tracking

All allocated from the ~3790 bytes freed in Phase 0C:

| System | Bytes | Notes |
|--------|-------|-------|
| Delta discovery flags | ~19 | 1 bit per species, ~150 species |
| Delta research progress | ~150 | Per-species DexNav/quest data |
| Deoxys fragment tracking | ~4 | 4 fragments, state per fragment |
| **Total** | **~173** | Leaves buffer for other systems |

### 4D. Testing Checklist

- [ ] Wild encounters in each zone match the lore saturation rates
- [ ] Pokédex entries display correctly in HGSS dex view

- [ ] Evolution chains work for Delta→Delta progressions

### Branch Management Strategy

1. Always `git checkout -b feature/<name>` before pulling any community branch
2. Test on the feature branch before merging to `main`
3. Merge in phase order — respect dependencies (especially Phase 0 before any branch)
4. If two branches modify the same files, merge sequentially and resolve conflicts between them before committing
5. Keep `RHH/master` as the upstream remote; merge upstream updates only between major phases to avoid mid-phase conflicts

### Verification Strategy

After completing each phase:

1. **Build check** — `make -j$(nproc)` completes with no errors
2. **Boot test** — ROM boots in mGBA, new game starts without crash
3. **Save/load test** — Save, close emulator, reload — no save corruption
4. **Feature test** — Each feature added in that phase is exercised in-game
5. **Regression test** — Features from prior phases still work (battles, menus, overworld, save)
6. **ROM size check** — Monitor with `ls -lh *.gba`; stay within 32MB limit

**End-to-end validation (after all phases):**

Start new game → custom Delta starter selection → explore overworld with follower → encounter Delta species in the wild → battle with Delta type matchups → check Quest Log → check HGSS Pokédex → save and reload cleanly → open Town Map showing Holon region
